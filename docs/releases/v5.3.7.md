# Velix v5.3.7 Release Notes

**Release Date:** October 18, 2026  
**Status:** Stable  
**Release Tag:** `v5.3.7`  

---

## Overview

Velix **v5.3.7** addresses critical stability, developer experience, and web standards compliance issues across the Velix monorepo ecosystem.

---

## Key Fixes & Improvements

### 1. Web Vitals & `PerformanceObserver` Cross-Browser Guards
- **Issue:** Firefox and Safari logged `entryTypes layout-shift ignoré, car non pris en charge.` when monitoring Cumulative Layout Shift (CLS).
- **Resolution:** Added feature detection checking `PerformanceObserver.supportedEntryTypes` before registering observers for `paint`, `largest-contentful-paint`, `layout-shift`, and `navigation` in `packages/velix/server/devtools.ts`.

### 2. Monorepo HMR Client & MIME-Type Compliance
- **Issue:** Browsers threw MIME type blocking errors on `/__velix/hmr-client.js` due to 404 responses missing `Content-Type` headers when dev was invoked from workspace subfolders like `website/`.
- **Resolution:**
  - Expanded search paths to traverse monorepo parent directories and sibling package distributions.
  - Guaranteed `Content-Type: application/javascript; charset=utf-8` on all responses, with automated fallback stubs.
  - Bundled and synchronized `hmr-client.js` into `@teamvelix/velix/dist/`.

### 3. CSS Specification Compliance (Misplaced `@import`)
- **Issue:** Modern CSS engines rejected Google Font `@import` directives placed after `@import "tailwindcss"` in `globals.css` with: `La règle « @import » n’est pas permise après toute règle valide autre que @charset et @layer`.
- **Resolution:** Relocated font imports to declarative `<link>` tags in `layout.tsx`, ensuring pure CSS compliance and faster parallel resource fetching.

### 4. Invalid CSS Directives Purged
- **Issue:** Unknown property warnings for `.[velix:ssr] { velix: ssr; }`.
- **Resolution:** Completely purged the invalid declaration from stylesheets and generation logic.

### 5. Monorepo Dependency Resolution
- **Issue:** Internal package builds threw `ERR_PNPM_NO_MATCHING_VERSION` when referencing unreleased sibling versions via npm.
- **Resolution:** Configured `link-workspace-packages=true` in `.npmrc` and linked monorepo dependencies via `workspace:*`.
